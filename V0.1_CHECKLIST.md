# v0.1.0 — Broadcast checklist

**Target date:** September 20, 2026

**Status as of September 14:** Basic broadcast logic is implemented. Current work
focuses on lifecycle cleanup and verifying actual media delivery.

This checklist tracks the release described in [ROADMAP.md](ROADMAP.md).
Completed implementation items do not replace the release checks below.

## Implemented

- [x] Create the Go HTTP server and serve the browser demo.
- [x] Add browser controls for publishing and watching.
- [x] Negotiate publisher and viewer connections using non-trickle HTTP signaling.
- [x] Implement Opus audio and VP8 video packet forwarding.
- [x] Register rooms and reject a second publisher in an occupied room.
- [x] Reject viewers until both publisher tracks are available.
- [x] Track viewers and clean up failed or closed viewer connections.
- [x] Clean up a failed or closed publisher, close its viewers, and release its room.
- [x] Protect replacement rooms from repeated cleanup of an old room.
- [x] Reject viewer registration after room cleanup and close rejected connections.

## Remaining implementation and automated verification

- [x] **Next:** Add an integration test covering SDP negotiation and actual audio
  and video packet delivery from a publisher through the SFU to a viewer.
- [ ] Add periodic PLI (Picture Loss Indication) requests to ask the publisher for
  video keyframes, allowing late viewers to begin decoding.
- [ ] Finish signaling timeout handling: enforce an ICE gathering deadline and
  clean up provisional connections on timeout or request cancellation.
- [ ] Bring viewer request validation in line with the documented signaling
  contract, including body limits, room IDs, and SDP offers.
- [ ] Add graceful shutdown that stops HTTP serving and closes active peers.
- [ ] Run the complete test suite with the race detector: `go test -race ./...`.

## Release acceptance checks

- [ ] Confirm one browser viewer receives both audio and video.
- [ ] Confirm two viewers can watch the same publisher for 30 minutes without
  interruption.
- [ ] Confirm starting a second room does not affect the first room.
- [ ] Confirm a viewer can disconnect and reconnect without restarting the server
  or interrupting another viewer.
- [ ] Confirm a publisher can disconnect and reconnect using the same room ID
  without restarting the server.
- [ ] Confirm publisher disconnect removes its room and closes its viewers
  without leaking goroutines.
- [ ] Confirm a late viewer begins displaying video within a few seconds.
- [ ] Confirm server shutdown closes active connections cleanly.

## Documentation and release

- [ ] Update the README's project status and setup/run instructions.
- [ ] Document API requests, responses, and error behavior.
- [ ] Document current limitations and a repeatable manual browser smoke test.
- [ ] Record acceptance-check results and any remaining limitations.
- [ ] Write brief release notes and tag `v0.1.0` after release checks pass.

## Deferred beyond v0.1

Multi-publisher conferencing, renegotiation, deliberate NACK/retransmission work,
simulcast, congestion control, authentication, persistence, and recording are
outside this release's scope.
